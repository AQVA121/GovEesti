# GovEesti

Long-run performance data for Estonian government ministries, presented in
context rather than in isolation. A fork/adaptation of
[Govviz](https://github.com/Egly443/Govviz) (UK) — same architecture and
approach, Estonian ministries and data sources.

Built with **Vite + React + TypeScript**, **TanStack Router** (file-based
routing), **Tailwind CSS v4**, **Recharts**, and **lucide-react**.

**Status:** early-stage fork. Source research for the first 19 indicators is
complete and live-verified against real APIs (`docs/INDICATORS-ee.md`); the
app shell has been adapted for Estonia (this step); no real data has been
fetched into the running dashboard yet — every chart currently renders the
honest "no source yet" placeholder. See [`docs/BRIEF.md`](docs/BRIEF.md) for
the full fork plan and current stage, and [`CLAUDE.md`](CLAUDE.md) for
contributor/agent guidance.

## Ministries

Sotsiaalministeerium (Social Affairs), Haridus- ja Teadusministeerium
(Education and Research), Siseministeerium (Internal Affairs), Justiits- ja
Digiministeerium (Justice and Digital Affairs), Kaitseministeerium (Defence),
Rahandusministeerium (Finance), Kliimaministeerium (Climate), and Majandus- ja
Kommunikatsiooniministeerium (Economic Affairs and Communications).

> **Real data only.** Every chart is meant to show real data fetched from
> official sources (Statistikaamet, Eurostat, TAI, World Bank and others) —
> never fabricated or interpolated. A series with no wired source renders an
> explicit "no source yet" placeholder rather than an invented trend. See
> `sourceUrl` on each series in `src/components/departments.ts`, and
> `docs/INDICATORS-ee.md` for the full source research behind each indicator.

## Non-goals

GovEesti does not centralise primary government data, replace Statistikaamet/
Eurostat methodology, publish restricted microdata, bypass disclosure
control, or certify official statistics. See `DATA-LICENCE.md` for
per-source licence status (not yet fully audited — see BRIEF.md §7, Этап 10).

## Getting started

```bash
npm install
npm run dev      # start the dev server (http://localhost:5173)
npm run build    # production build to dist/
npm run preview  # preview the production build
npm run typecheck
```

> A local build without CI-baked data shows placeholders for every series —
> there is no illustrative/fabricated fallback by design. See BRIEF.md §7
> (Этап 5) for the plan to wire real fetchers in, one indicator at a time.

## Local real-data builds

Once fetchers exist (BRIEF.md §7, Этап 5), the production deploy will fetch
live official-source data before building. To reproduce one or more series
locally:

```bash
npm run fetch-data -- --only=<series-id>
```

The fetcher writes `src/generated/seriesData.ts`. That file is kept empty in
git and populated by CI, so restore it to the committed empty form after
local testing unless you are intentionally inspecting generated data.

## Overview treemap

`/overview` is the landing page: a whole-of-government heatmap. Each
ministry block is currently sized **equally** (no real per-ministry budget
figure has been sourced yet — see `SPEND_BASIS` in `departments.ts`), and
within a block each indicator tile is weighted Finviz-style (hero > core >
supporting). Tile **colour** is a red→amber→green RAG score: where a
published target/standard exists, green means at or beyond that benchmark.
Indicators with **no external benchmark** are scored against their own
history and shown **desaturated**. Unsourced indicators are greyed with no
value. Clicking a tile opens its full `TrendPanel` chart in a modal.

## Routing

`/` redirects to `/overview`. Each ministry is reachable at `/<code>`, e.g.
`/soc`, `/edu`, `/int`, `/just`, `/def`, `/fin`, `/clim`, `/econ`.
