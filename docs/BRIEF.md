# Govviz-Estonia — техническое ТЗ / бэклог для вайбкодинга

Референс: [Govviz](https://github.com/Egly443/Govviz) (UK).
Подход: форк и адаптация — берём код и архитектуру напрямую, адаптируем
под Эстонию.

Язык результата: **английский**, как в оригинале (не эстонский и не
русский по умолчанию — см. раздел 2 про язык).

---

## 1. Стратегия: форк и адаптация

Берём Govviz как основу напрямую — форк репозитория, затем удаление/
адаптация под Эстонию. Это ускоряет вайбкодинг: не нужно писать заново то,
что уже написано и работает.

- Компоненты без британской специфики (`TrendPanel.tsx`, `GovTreemap.tsx`,
  `Modal.tsx`, `TopNav.tsx`, общая структура роутинга) — переиспользуются
  почти без изменений, агент адаптирует пропсы/стили, не пишет с нуля.
- `scripts/build-data.mjs` — переиспользуется как **каркас паттерна**
  (обёртка try/catch на источник, `setSrc()`, хеширование байт источника,
  ретраи), но сами функции-фетчеры под конкретные UK-таблицы (`ons()`,
  парсер конкретных ONS CDID) заменяются на эстонские (готовый `pxweb()`
  хелпер, см. раздел 8) — это не тот код, который стоит копировать 1:1,
  он специфичен под структуру британских источников.
- `scripts/check-open-data.mjs`, guard-логика на `validRange` — хороший
  кандидат на copy+adapt, логика универсальна.
- `docs/conformance/probe-15-lines.mjs` — можно скопировать почти
  дословно, заменив базовый URL.
- Данные по департаментам, сами показатели (`departments.ts`,
  `INDICATORS.md`) — не переиспользуются, это чисто британский контент,
  пишутся заново под Эстонию (см. раздел 5).

**Практический вывод:** имеет смысл начать не с пустого репозитория (как
планировалось раньше), а с форка Govviz, после чего первая задача агенту —
"пройтись по репозиторию и вычистить всё британское специфичное (данные,
департаменты, MCP, conformance-отчёты), оставив архитектурный каркас".
Это быстрее, чем генерировать каркас с нуля.

## 2. Стек (как в оригинале, работает хорошо)

### Язык интерфейса и контента: английский

Как в оригинале — весь UI, названия показателей, подписи осей, тексты
about/data-страниц, README и метаданные серий (`title`, `producer`,
`compiler` и т.д.) — **на английском**, не на эстонском и не на русском.
Это не финальная точка выбора, а базовая настройка с первой итерации:
- Названия эстонских министерств в UI — английские официальные названия
  (Ministry of Social Affairs, Ministry of the Interior и т.п.), а не
  транслитерация эстонских (Sotsiaalministeerium остаётся только как
  внутренний код/справочный термин в брифе, не как то, что видит
  пользователь).
- Названия показателей источников (Statistikaamet, TAI) переводятся на
  английский при отображении — большинство таблиц PxWeb и так отдают
  `text`/`valueTexts` на английском при запросе с `/en/` в пути API
  (см. примеры в разделе 9) — значит дополнительный перевод по большей
  части не нужен, только выбор правильного языкового параметра запроса.
- Эстонский/русский интерфейс — не задача MVP, при желании добавляется
  позже (см. раздел 11), но не должен быть дефолтом или помехой для
  соответствия оригиналу.

## 3. Область охвата MVP (пересмотрено после чтения essay/about/data)

Ключевой вывод из `docs/blog-open-data-for-ai.md`: ядро ценности Govviz — не
UI, а **слой доверия к данным** ("AI-ready series profile"). Это дёшево
заложить сразу и дорого пристраивать потом, поэтому часть того, что раньше
планировалось "выкинуть", теперь остаётся — но в облегчённой форме.

**Убираем на первом этапе** (действительно надстройка, можно вернуть позже):
- MCP-сервис (`tools/mcp/`) — открытый интерфейс для ИИ-агентов
- Полный conformance-suite с отчётами (`docs/conformance/*.html`, health-history)
- DCAT/JSON-LD граф, OpenAPI-контракт, `mcp.json`
- `docs/policy-*`, `docs/blog-*`, аналитика посещений

**Оставляем ядро (визуальное):**
- Дашборд по министерствам с трендами
- Overview-treemap (Finviz-style) с RAG-раскраской
- Реальные данные only, с честным плейсхолдером при отсутствии источника

**Добавляем в ядро (раньше недооценил — это дёшево и есть суть проекта):**
- `validRange` — диапазон правдоподобия на каждый показатель, guard-проверка
  в билде (отклоняет "правдоподобное, но неверное" значение)
- Разделение `producer` (кто выпустил данные) и `compiler` (что мы с ними
  сделали) в метаданных каждой серии — не выдавать свою обработку за
  официальное подтверждение источника
- `licence` — аудит лицензии **по каждому источнику отдельно**, не единый
  штамп на весь каталог (см. раздел 8)
- Простой JSON-эндпоинт на серию (`/data/series/{id}.json` + `data.csv`) —
  минимальная версия open-data слоя, без полного DCAT/CSVW аппарата

## 5. Источники данных (заменяют британские)

| UK-источник (оригинал) | Эстонский аналог | Формат/качество |
|---|---|---|
| ONS timeseries API | **Statistics Estonia (Statistikaamet)** — PxWeb API, andmed.stat.ee | 🟢 JSON, без ключа |
| World Bank | World Bank API (без изменений) + **Eurostat API** | 🟢 JSON |
| gov.uk / departmental XLSX | **avaandmed.eesti.ee** | 🟡 требует API-ключ, каталог-указатель, а не единый чистый API |
| NHS England | **Tervise Arengu Instituut (TAI)** — statistika.tai.ee | 🟢 тот же PxWeb, без ключа |
| HMRC | **Maksu- ja Tolliamet (EMTA)** open data | 🔴 файлы (CSV/XLSX) по прямой ссылке, не API — нужен файловый парсер |
| MHCLG housing | Statistikaamet (жильё) + **Maa-amet** (кадастр/цены) | 🟡 Maa-amet — есть WMS/WFS геосервисы (CC BY 4.0), но это карты/кадастр, не готовые тайм-серии; страница со статистикой цен на недвижимость — JS-рендер, нужна ручная проверка |
| OBR/NAO fiscal | **Rahandusministeerium** (бюджет), **Eesti Pank** (макро) | 🔴 Eesti Pank — см. ниже; Statistikaamet частично закрывает бюджетные таблицы (🟢, уже подтверждено на примере госдолга); есть также портал расходов ведомств RTK saldo.rtk.ee (см. ниже) — статус нестабильный |

### Результаты разведки (проверено вручную, см. раздел 9)

- Statistikaamet и TAI используют **один и тот же движок PxWeb** → один
  парсер-хелпер закрывает оба источника (экономия времени на Этапе 5).
- Здравоохранение: изначальная гипотеза про Tervisekassa была не совсем
  точной. Все таблицы по здоровью в Statistikaamet — архивные, обрываются
  на 2014–2015 гг. Актуальный и активно обновляемый источник — TAI
  (statistika.tai.ee), а не Statistikaamet и не Tervisekassa напрямую.
  **Вывод: гипотезы про источники нужно всегда проверять руками — то, что
  "логично" по структуре министерств, не всегда совпадает с реальным
  расположением данных.**
- avaandmed.eesti.ee подтверждён как более сложный источник (API-ключ,
  фрагментарная документация) — не первый кандидат для быстрых побед в MVP.
- **Eesti Pank**: публичного REST/API-эндпоинта прямым перебором не нашёл —
  `statistika.eestipank.ee` это JS-SPA. Практический обходной путь: часть
  монетарной/банковской статистики по Эстонии (ставки, депозиты) доступна
  через **ECB Statistical Data Warehouse (SDW)**, раз Эстония в еврозоне —
  не нужно ждать доступа именно к Eesti Pank. Если нужны данные, которых
  нет в ECB SDW — заложить отдельную задачу агенту на ручной разбор
  сетевых запросов сайта statistika.eestipank.ee через DevTools браузера.
- **EMTA (налоговая)**: открытые данные — это файлы для скачивания
  (CSV/XLSX по прямой ссылке на emta.ee), не queryable API. Похоже на то,
  как в оригинале обрабатывался британский HMRC — понадобится файловый
  парсер (fetch → parse CSV/XLSX), а не JSON-хелпер как для PxWeb.
- **Maa-amet**: у него есть полноценная геопространственная инфраструктура
  (WMS/WFS, стандарт OGC, лицензия CC BY 4.0) — хорошо подходит для
  карт/кадастра, но это не готовые тайм-серии для трендов. Отдельная
  страница со статистикой цен на недвижимость (`htraru`) — JS-рендер,
  через `curl` содержимое не вытянулось, нужна ручная проверка в браузере
  или через DevTools на Этапе 2.
- **Rahandusministeerium / RTK (расходы ведомств)**: нашёл многообещающий
  портал `saldo.rtk.ee/saldo-app/avaandmed` — публикует файлы платежей
  министерств и госорганов (потенциально закрывает VFM-показатели —
  расходы по ведомствам, как в оригинале). Но найден и парламентский
  запрос от марта 2025 о пропавших данных за 2024–2025 гг., а прямой
  запрос сейчас вернул 404/редирект без содержимого. **Статус: нестабилен,
  требует ручной проверки в браузере перед тем, как закладывать как
  источник** — не первый кандидат для быстрых побед.

## 6. Индикаторы — на каждое министерство 3 «линзы» (по образцу INDICATORS.md)

- **C — Competence/performance**: прямые метрики работы (время ожидания,
  раскрываемость, % выполнения нормативов и т.п.)
- **VFM — Value for money**: расходы на голову населения / на единицу результата
- **L/O — Leading/root-cause или Outcome**: то, что нельзя легко "подкрутить"
  (независимая статистика, обследования, регуляторы)

Для каждого показателя фиксировать (расширено по мотивам AI-ready profile):
- название, единицы, периодичность, охват (страна/регион)
- источник + прямая ссылка на API/датасет
- 🟢🟡🔴 сложность фетчинга (M-ось, см. ниже)
- допустимый диапазон значений (`validRange`) для guard-проверки
- `producer` (кто официально выпускает) отдельно от `compiler` (что мы сделали)
- лицензия именно этого источника (не общая по каталогу)
- `revisionStatus` (предварительно/финально) — если источник это публикует

### T×M — вспомогательная ось приоритизации (не для отчётности, а для выбора)

Из эссе: не гнаться за лёгкими источниками. Самый ценный показатель —
высокое доверие (T3, официальная статистика) при плохой машиночитаемости
(M1–M2, нужен скрейпинг/парсинг). Именно такие показатели дают эффект
"AI-ready" — превращают нечитаемый машиной официальный источник в честный
API. Простые T3/M4 источники (уже готовый чистый JSON, напр. Statistikaamet)
тоже нужны — как быстрые победы для MVP, но не должны быть единственным
критерием отбора.

Создать файл `docs/INDICATORS-ee.md` по этому шаблону перед началом кодинга.

      (что сделал GovEesti — даже "direct pass-through, no transformation"
      теперь указывается явно, не подразумевается). `ratioSeries()`
      обновлён под новую сигнатуру. `TrendPanel.tsx`: строка "Source: ..."
      теперь читает `producer`. Заполнено для всех 19 показателей +
      честного плейсхолдера Justiits — тексты перенесены из уже готовой
      Этап-3-спеки (`docs/INDICATORS-ee.md`), не придуманы заново.
      **Реальная находка, не гипотетическая**: у трёх derived-показателей
      (`soc-health-spend-per-capita`, `edu-pupil-teacher-ratio`,
      `def-personnel-per-1000`) операция деления была прописана ПРЯМО
      ВНУТРИ старого поля `source` (например, "Statistikaamet (RR056
      COFOG expenditure ÷ population)") — то есть буквально приписывала
      первоисточнику то, что вычислил GovEesti. Очищено: `producer`
      теперь называет только организацию(и), деление — только в
      `compiler`/`methodology`. Проверено визуально: модалка
      `soc-health-spend-per-capita` показывает чистое "Source:
      Statistikaamet (...)", вычисление — отдельно в "How it's
      calculated". `npm run build` (включая guard-проверку из пунктов 1–2)
      проходит на реальных и пустых данных.

**Этап 7 полностью завершён** (все 3 пункта чек-листа).

## 8. Практические правила вайбкодинга для этого проекта

1. Маленькие проверяемые задачи. "Добавь один показатель" — хорошо.
   "Сделай весь Sotsiaalministeerium" — плохо, агент начнёт додумывать данные.
2. Явно запрещать синтетические/"правдоподобные" данные как fallback —
   вместо этого честный плейсхолдер "нет источника".
3. Перед написанием парсера — агент должен показать реальный пример ответа
   API (не полагаться на память модели об эстонских источниках).
4. Частые небольшие коммиты — поломка одного фетчера не должна ронять
   весь пайплайн.
5. Раз в несколько итераций — просить агента пересмотреть уже написанные
   фетчеры на предмет дублирования логики (общие хелперы вместо копипасты).

## 9. Разведка API (сделано, можно переиспользовать)

Ниже — рабочие примеры запросов, проверенные вручную. Их можно сразу
показать агенту на Этапе 5 как отправную точку для первого фетчера
(экономит цикл "агент угадывает формат API").

### Statistikaamet — список категорий
```
GET https://andmed.stat.ee/api/v1/en/stat
```

### Statistikaamet — поиск таблицы по ключевому слову
```
GET https://andmed.stat.ee/api/v1/en/stat?query=government%20debt
```

### Statistikaamet — метаданные таблицы (коды переменных)
```
GET https://andmed.stat.ee/api/v1/en/stat/majandus/rahandus/valitsemissektori-rahandus/valitsemissektori-tulud-kulud/RR061.px
```

### Statistikaamet — реальные данные (POST, обязателен для данных, не GET)
```
POST https://andmed.stat.ee/api/v1/en/stat/majandus/rahandus/valitsemissektori-rahandus/valitsemissektori-tulud-kulud/RR061.px
Content-Type: application/json

{
  "query": [
    {"code": "Näitaja", "selection": {"filter": "item", "values": ["2"]}},
    {"code": "Aasta", "selection": {"filter": "item", "values": ["2019","2020","2021","2022","2023","2024"]}}
  ],
  "response": {"format": "json"}
}
```
Проверено вживую — вернуло реальный госдолг Эстонии к ВВП: 9.0% (2019) →
19.1% (2020) → 18.4% (2021) → 19.2% (2022) → 20.2% (2023) → 23.5% (2024).

### TAI (здравоохранение) — тот же паттерн, другой домен
```
GET https://statistika.tai.ee/api/v1/en/Andmebaas
GET https://statistika.tai.ee/api/v1/en/Andmebaas/04THressursid/11HAHaiglad/HH08.px
```
Тоже PxWeb → тот же код фетчера, что и для Statistikaamet, с заменой базового
URL. `HH08.px` проверен вживую 2026-09-04 — "Hospitals' annual average beds…",
годы 2003–2024, реальные данные по койкам (`Näitaja=0`, `Ravivoodi liik=0` =
итог по стране).

### Eurostat — dissemination API, GET only, без ключа
```
GET https://ec.europa.eu/eurostat/api/dissemination/statistics/1.0/data/{dataset}?format=JSON&geo=EE&lang=EN
```
Проверено вживую 2026-09-04 на нескольких датасетах. **Важно**: сначала
запросить без доп. фильтров, чтобы узнать реальные имена размерностей и
коды категорий из ответа (`dimension.<code>.category.index`) — имена не
всегда совпадают с "логичным" вариантом (напр. `hlth_hlye` использует
размерность `hlth_hle`, а не `indic_he`; `env_air_gge` использует
`src_crf=TOTXMEMO`, а не произвольный код сектора). Подтверждённые рабочие
запросы:
```
GET .../data/hlth_hlye?format=JSON&geo=EE&sex=T&hlth_hle=HLY_Y0&lang=EN   → здоровые годы жизни при рождении
GET .../data/demo_mlexpec?format=JSON&geo=EE&sex=T&age=Y_LT1&lang=EN     → ожидаемая продолжительность жизни
GET .../data/env_air_gge?format=JSON&geo=EE&airpol=GHG&unit=THS_T&src_crf=TOTXMEMO&lang=EN  → парниковые газы, всего
GET .../data/isoc_r_broad_h?format=JSON&geo=EE&lang=EN                  → домохозяйства с широкополосным доступом
```
Формат ответа — JSON-stat (значения в плоском объекте `value` с числовыми
индексами, расшифровка индексов — в `dimension.time.category.index`), не
путать с форматом PxWeb (`data`/`columns` у Statistikaamet/TAI) — это два
разных парсера, не один общий хелпер.

### Eesti Pank — не PxWeb, обходной путь через ECB SDW
Прямого API не нашли (`statistika.eestipank.ee` — JS-приложение, перебор
типовых путей `/api`, `/rest`, `/sdmx` вернул 404). Раз Эстония в еврозоне,
для монетарной/банковской статистики рабочий обходной путь — **ECB
Statistical Data Warehouse**, у которого есть открытый SDMX/REST API с
разбивкой по странам еврозоне, включая Эстонию:
```
GET https://data-api.ecb.europa.eu/service/data/{dataflow}/{key}?format=jsondata
```
Конкретный `dataflow`/`key` для нужного показателя (например, ставки по
кредитам домохозяйствам) нужно будет подобрать на Этапе 5 через каталог
ECB Data Portal — это отдельная небольшая задача агенту.

### EMTA (налоги) — файлы, не API
Открытые данные лежат как готовые файлы (CSV/XLSX) по прямым ссылкам на
странице `emta.ee/en/.../statistics-and-open-data`, обновляются по
расписанию (например, налоговые поступления — 2-го числа каждого месяца).
Конкретные ссылки подтверждены вживую 2026-09-04 (хостятся отдельно, на
`ncfailid.emta.ee`, не на `emta.ee`):
```
GET https://ncfailid.emta.ee/s/e4DneiWeKFfje6d/download/tasutud_maksud_kaesolev_aasta_eng.csv   (текущий год)
GET https://ncfailid.emta.ee/s/K8snLYNdZnqJCRn/download/tasutud_maksud_varasemad_aastad_eng.csv (прошлые годы)
```
**Но:** это не готовый временной ряд, а подетальные микроданные —
`Registry code, Name, Type, County, Activity, Year, State taxes Q1–Q4,
Labour taxes Q1–Q4, Turnover Q1–Q4, Number of employees Q1–Q4`, одна
строка = одна компания за год (~62 МБ). Фетчер здесь не JSON-запрос, а:
скачать файл → распарсить CSV → **агрегировать** по нужному разрезу
(тот же xlsx/csv-парсер, что и в оригинальном `build-data.mjs` для
британских источников, плюс шаг агрегации, которого не было в оригинале).
Ссылки на файлы — Nextcloud share-токены (`/s/<token>/`), которые могут
измениться при переиздании — фетчер должен переоткрывать HTML-страницу
источника и вытаскивать текущий `href`, а не хранить URL как константу.
Учитывая, что налоговая нагрузка (% ВВП) уже закрыта World Bank
`GC.TAX.TOTL.GD.ZS` (✅, простой JSON), EMTA-микроданные — кандидат v2, не
обязательный показатель v1.

### Justiits-portal (`statistika.justdigi.ee`) — статичные CSV на Drupal-сайте
Не PxWeb и не JSON:API (проверено — `/jsonapi` даёт 404, JSON:API-модуль не
включён), а обычный Drupal 10 сайт, который на странице
`/en/crime-statistics` линкует готовые CSV прямыми ссылками вида
`/sites/default/files/<yyyy-mm>/<Name>_eng.csv`. Пример, проверенный
вживую 2026-09-04:
```
GET https://statistika.justdigi.ee/sites/default/files/2026-02/Kuriteod%20kokku_masskuriteod_eng.csv
```
`text/csv`, `;`-разделитель, `Type of crime;Year;Number of Offences`,
реальные значения (Total 2024 = 28345, 2023 = 27465, …). Путь
дата-меченный и сдвигается при переиздании — фетчер должен парсить
`/en/crime-statistics`, находить актуальный `href` по тексту ссылки (не
хардкодить `/2026-02/...`), затем скачивать и парсить сам CSV. Разделов
про суды (courts) или тюрьмы на этом портале нет вообще — только
crime-statistics, victim-survey, overview-lobby-meetings.

### Практический вывод для Этапа 4 (каркас)
Стоит сразу написать один переиспользуемый хелпер `pxweb(baseUrl, path, query)`
для Statistikaamet/TAI, и отдельно — `fetchCsvOrXlsx(url)` для EMTA-подобных
файловых источников. Двух хелперов, вероятно, хватит на большинство
показателей — экономия по сравнению с оригиналом, где под каждый источник
UK был свой уникальный парсер (ONS, NHS, DEFRA и т.д. — все разные форматы).

**Подтверждено на Этапе 5 (2026-09-05), с поправками.** Реализовано три
хелпера, не два: `eurostat(dataset, params)`, `pxweb(url, query)` (сигнатура
проще предсказанной — один URL-параметр, не два) и отдельная
не-переиспользуемая функция `intRecordedCrimes()` для скрейпинга CSV со
страницы `statistika.justdigi.ee` (EMTA-подобный файловый источник
`fetchCsvOrXlsx()` пока не понадобился — все 19 подключённых на Этапе 5
показателей обошлись без EMTA). `pxweb()` изначально поддерживал только
годовой формат дат; понадобилось расширение (`pxwebDate()`) для
квартальных серий (`"2019Q3"`), когда дошли до `econ-unemployment-rate`.
Прогноз "двух хелперов хватит на большинство показателей" подтвердился
почти точно — 18 из 19 показателей закрыты `eurostat()`/`pxweb()`/`wb()`
(уже существовавшим из UK-оригинала), только один потребовал скрейпинга.

## 10. Масштаб: реалистичные ожидания

Оригинальный Govviz в текущем виде — 124 показателя, 17 ведомств. Это не
стартовая точка, а результат долгой (вероятно, многомесячной) итеративной
работы. Реалистичный MVP для Эстонии:

- **v1**: 30–40 показателей, 7–8 министерств (см. раздел 3), из них
  осознанно часть с плейсхолдером "источник ещё не подключён" — это
  нормально, так делает и сам оригинал (`*no data locally*` встречается
  даже в зрелой версии).
- **v2**: расширение вширь (больше показателей на министерство) и вглубь
  (сравнение с соседями — Латвия, Литва, Eurostat-агрегаты — так же, как
  оригинал сравнивает UK с Германией/Францией по некоторым сериям).
